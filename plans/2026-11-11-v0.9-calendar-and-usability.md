# Феория 0.9 - календарь и понятный путь к службе

## Видение

Человек находит храм по знакомому ориентиру, видит отдельно подтвержденное расписание сегодня/завтра и доступные тексты, открывает книгу и спокойно читает ее непрерывной лентой. Режимы текста не ломаются на маленьком экране. Микрофон показывает состояние и услышанные слова, завершение записи сохраняет результат. API Азбуки дополняет книгу только проверенными данными нужной даты и подтвержденными источниками; сохраненные тексты и объяснения доступны после холодного запуска без интернета

## 1. Разведка - завершена до реализации

База: выпущенная 0.8, commit 8ee949f. Рабочее дерево чистое до начала этапа

Что работает: полное опубликованное последование по дате через /worships, непрерывное чтение, опубликованные частичные переводы, кеш книги, поиск по названию и рядом, загрузка расписаний HTML/PDF/OCR

Реальные дефекты после воспроизведения/чтения кода:

- Запрос "метро сухаревская троицы" возвращает другой храм на Большой Сухаревской площади. Поиск по точному названию "Троицы в Листах Москва" находит объект relation19595736. Нужен поиск по явному ориентиру даже при непустой обычной выдаче, с адресами и без автоматического выбора неоднозначного результата
- Сайт hram-troicy.ru/raspisanie/ публикует события на 11 и 12 ноября, но юридическая строка в body становится ложной секцией другого здания и блокирует разбор
- TodayScreen смешивает отсутствие расписания, чтение, типовой порядок и нижние действия. На вкладке выбранного дня может показываться ближайшая служба другой даты
- BookModePicker делит тесную строку на три равные FilterChip. На 320dp подпись "Оригинал" не помещается; прежние тесты доступности кнопок не проверяли реальный перенос текста
- BookSearchSheet скрывает partial transcript, а кнопка остановки вызывает cancel/reset вместо finishListening. Backend игнорирует callbacks начала речи и уровня звука
- Авторизованный Safari открывает документацию, но реальный GET /api-v2/daytype/2026-11-11 возвращает 401 JWT Token not found. Секретов Азбуки в настройках проекта нет. Подготовлена loopback-форма для отдельного доступа; API-интеграция ожидает действующий токен, независимые исправления продолжаются

Топ-3 по пользе/усилиям: точный поиск и исправление реально опубликованного расписания; понятная структура экрана и надежные переключатели; завершение/обратная связь короткого голосового поиска

## 2. Быстрые исправления

- Поиск: явный ориентир -> координаты ориентира -> ограниченный поиск храмов вокруг -> ранжирование по названию и расстоянию, сохранение адресов/источников и неоднозначности
- Расписание: исправить ложное определение чужого здания, сохранив защиту от настоящего чужого расписания, старых дат и отмен
- Чтение: измеряемые подписи режимов, однострочный текст без обрезки; адаптивный выбор режима при крупном шрифте
- Микрофон: различимые состояния подготовки/захвата/обработки, промежуточная фраза, реальный уровень при наличии callback, "Готово" завершает запись, отмена отдельно

Каждая принятая порция - ревью, затронутые проверки, отдельный коммит. Один владелец Gradle/эмулятора - root

## 3. Основная функция - проверенные дополнения из API

До реализации: живые ответы на будний день 2026-11-11, следующий день 2026-11-12, воскресенье 2026-11-15, Рождество 2026-01-07 и день большого подвижного праздника, дату которого сначала сверяем с календарем источника

Проверяем day + day-direct + daytype, затем связанные texts/holidays/saints/troparia. Сверяем дату, связи, фактические тексты, смысл explanation, nullable поля и источники. Сохраняем обезличенные ответы и наблюдения без токена/пароля

Из изученной схемы известно: day-direct в основном возвращает ID, explanation не гарантирует перевод, readings не имеют отдельной стиховой схемы, каноны содержат redirectUrl, а расписаний приходов и полного порядка службы в 15 маршрутах нет. Не приписывать API несуществующие поля. Наличие справочника не подтверждает живой состав данных

Полезное подключаем в отдельный поставщик календарных данных, не заменяя работающую книгу вслепую. Публикации и объяснения имеют источник, дата и вариант службы сохраняются. Никаких сгенерированных молитв и автоматического объявления пояснения переводом. Пароль/общий токен не вшивается в APK. Рабочий способ доставки данных на телефон проверяется отдельно, локальный эксперимент не считается интеграцией

## 4. Полировка - три законченных прохода

1. Новичок: ориентир -> правильный адрес -> сегодня/завтра -> нужный текст. Одна ясная основная кнопка, отдельные поверхности расписания/чтения/сведений, справка типового порядка раскрывается отдельно
2. Чтение: 320/360dp, fontScale 1.0/1.3/1.5/2.0, три режима, ручная прокрутка через главы, возврат. Проверять переносы TextLayoutResult и реальные PNG, а не только наличие узла
3. Слабая сеть/микрофон: загрузка -> обрыв -> сохраненная книга -> холодный офлайн-запуск; подготовка/слушание/partial/готово/ошибка/отказ в разрешении/уход в фон. Реальные аудиовозможности не считать проверенными по подставленным callbacks

Дизайн-основания: Apple HIG Layout (обновление 9 сентября 2026) https://developer.apple.com/design/human-interface-guidelines/layout.md и Android Compose accessibility https://developer.android.com/develop/ui/compose/accessibility/api-defaults. Группы разделяются контейнерами и фоном, интерактивные цели от 48dp, независимые действия с промежутком от 12dp. При большом шрифте перестраиваем расположение вместо уменьшения текста

## 5. Финальный QA и выпуск

- Unit и Android-проверки затронутых сценариев, затем общая релевантная регрессия и lint
- Живой поиск по исходной фразе и другим ориентирам, точные даты расписания нескольких храмов
- Связь и отсутствие сети, поврежденные/неполные данные, сохранение правильной даты/редакции книги, повторный запуск
- Независимое ревью изменений; найденные реальные дефекты исправляем до принятия итерации, не придумываем дефект ради отчета
- Версия/README/changelog отражают фактическую реализацию. Собрать и подписать APK прежним ключом, проверить установку и точный артефакт
- Не объявлять API, офлайн или релиз готовыми, пока путь на телефоне не проверен. Финальный RELEASE-коммит только после приемки

## Блокеры

- Доступ к API получен и проверен. Пароль не сохранен, рабочий JWT находится только в игнорируемом приватном каталоге
- Способ защищенной доставки API в пользовательский APK выбирается после проверки ответов и доступной инфраструктуры; новый секрет не публикуется в репозитории или сборке

## Идеи на потом

- Непрерывное прослушивание с автоматической синхронизацией: отдельная функция после измерения качества текущего распознавания
- Иллюстрации, полная библиотека житий, дополнительные справочники вне основного пути чтения

## Проверенные итерации 0.9

### Поиск по ориентиру и юридическое название прихода

- Поиск станции и храмов вокруг нее дополняет непустую прямую выдачу. Храмы с похожим названием остаются отдельными результатами с адресами
- Саморевью и независимое ревью исправили подмену явно указанного города, потерю запроса после станции "Троицкая", наследование признака приблизительного GPS и лишние задержки свежего кеша
- Сайт Троицы в Листах корректно разбирается с юридическим заголовком; чужой приход и отмененные службы остаются отклоненными
- Общая сборка: 741 unit-тест PASS. Android: все 14 сценариев ChurchDiscoveryScreenTest PASS. Проверки экрана чтения и больших шрифтов еще выявляют проблемы и не приняты

### API: подтвержденные факты до интеграции

- 64 реальных ответа по пяти датам, независимая проверка SHA. 22 пары original/explanation подтверждены публичной меткой "Перевод", 8 объяснений пустые, 2 не относятся к опубликованным переводам праздничной даты
- API не задает порядок службы. Чтения праздничных дат содержат ссылки с обозначениями служб, не полные стихи
- Refresh требует Authorization Bearer вместе с JSON-телом. Тело без заголовка вернуло 401; второй способ проверен успешно. Старый JWT после обновления остается действующим; срок выданного ключа 31 день
- Новый поставщик дополняет выбранную книгу точными переводами и отдельным контекстом дня. Полный текст остается из датированного /worships, стихи - из проверенного библейского источника
