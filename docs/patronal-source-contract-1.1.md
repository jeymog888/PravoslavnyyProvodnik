# Конкретное посвящение храма в источнике последования

Проверено 13 ноября 2026. Это подтвержденный сетевой контракт и вход следующей реализации, не готовая Android-функция

## Что установлено

Параметр `church` выбирает категорию храма. Он не задает конкретный престольный праздник. В полных литургиях обычного храма святого это оставляет два пропуска. Богородичный вариант может вместо пропусков печатать общие песнопения, отличающиеся от конкретного посвящения

Штатный параметр `patronal` задает конкретное событие. Его значение - `events[].id` из публичного календаря `https://azbyka.ru/worships/calendar/api/YYYY-MM-DD/`. Это не индекс `main_event`, не ID святого API и не WordPress ID Минеи

При принятом выборе источник убирает `bg_worships_church` и добавляет `bg_worships_patronal` с выбранным ID. Подпись option пустая. Поэтому нужен ранее подтвержденный календарный event и точная проверка ID в ответе. Отсутствие контрола не разрешает тихо принять базовый текст

Root независимо повторил сравнение Николая 22 мая: базовый ответ содержит два пропуска, выбранный ID - ни одного и другие конкретные тексты. Исследовательский набор включает 19 публичных ответов, без cookies, токена API или изменения профиля

## Общий поиск по имени

Публичный WordPress REST `https://azbyka.ru/worships/wp-json/wp/v2/minea` дает метаданные названий и ссылок. Снимок из 11 страниц содержит 1 100 уникальных записей; исходные ответы занимают 473 986 байт. Root отдельно проверил все хеши, уникальность, разрешенные поля и происхождение ссылок. Полные тексты и весь год календарей не скачивались

Простое серверное обращение с запросом "Николая" вернуло пустой результат при наличии названий с ударением. Локальный поиск должен нормализовать ударения и учитывать проверенные русские синонимы. "Троица" должна находить "Пятидесятница", а не только Троицкие монастыри

В снимке 865 фиксированных дат, 138 подвижных и 97 других заголовков. Одинаковые названия с разными датами и ID не объединять. Старостильная дата не всегда переводится прибавлением 13 суток; знак смещения относительно Пасхи также значим. После выбора требуется точный `minea_id` в календаре, а не первое похожее название

## Критерии Android-внедрения

- Выбор понятен по имени и уточняющему празднику; пользователь не обязан знать технический ID или дату заранее
- Конкретное посвящение входит в идентичность книги и кеша, сохраняется во всех связанных частях и не переносится между храмами
- Календарный event и ответ последования подтверждаются независимо. HTTP 200 сам по себе недостаточен
- Книга с непроверенным или исчезнувшим выбором не подменяется общим вариантом
- Отдельный русский перевод храмового песнопения сверяется с точным оригиналом и своим источником. Пакет календаря на дату службы не гарантирует перевод песнопения другого праздника
- До принятия нового текста прежняя книга и место сохраняются. После принятия проверяются холодное чтение без сети и несколько следующих элементов после найденной фразы

Полное местное последование по этому параметру не устанавливается. Он устраняет конкретный недостающий или общий храмовый текст; ежедневные памяти, сокращения и исполняемые кафизмы остаются самостоятельными проверками

## Реализация основы - 13 ноября 2026

В коде добавлены отдельный `patronalId` ключа и неизменяемый снимок календарного свидетельства в книге. Прежний null-вариант сохраняет JSON, hash и адреса кеша. Единую проверку выбранного ID используют обычное последование и оба шага полиелейного протокола. Несовпадение final URL или обычный HTTP 200 fallback не принимаются как выбранное посвящение

Дополнительно получены два настоящих ответа утрени 13 ноября с майским Николаем: основной event0 изменился с уровня6 на3, дополнительный стал явно пустым, patronal111300 сохранился. В теле подтверждены оба полиелейных псалма, Евангелие и великое славословие. Это совместимость параметров источника, не свидетельство местного исполнения

Репозиторий использует свидетельство из выбранного источника либо сохраненной проверенной книги. Составное бдение собирается только с одним согласованным снимком. Дополнительные русские пары даты посвящения не подменяют календарь, чтения или приоритет переводов даты самой службы

Общий локальный каталог содержит 1 100 исходных записей и их происхождение. Поиск различает иконы и святых, сохраняет разные празднования одного имени, обрабатывает обычные формы имен. Даты вычисляются по юлианскому календарю и православной Пасхе. Каталог дает кандидата, а не подтвержденный event: нужна следующая runtime-проверка точного `minea_id` в календаре

Проверены 19 source/repository, 8 identity и 18 catalog unit-сценариев. Общий набор - 1 288 тестов, 0 failures/errors, один прежний opt-in skip. Astra отдельно проверила протокол, происхождение HTML/каталога и математику дат. Найденные смешения Илии с Илиодором/союзом "или", форм Павел/Павла и повторные JSON-поля воспроизведены и устранены

Эта основа еще не подключена к пользовательскому выбору. До завершения функции остаются runtime resolver календаря, сохранение выбора только после проверенной книги, целостная смена обеих частей с возвратом к прежнему маршруту, понятный экран и Android-прогон с настоящей сетью/последующим отсутствием сети
