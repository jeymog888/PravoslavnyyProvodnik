# Приписной храм на странице контактов общего прихода

Принята предметная основа нового поставщика кандидатов. Подключение к AppContainer и полный путь до Android импорта - следующая отдельная порция. Этот документ не утверждает, что выбранный храм уже получает расписание через новый provider

## Что проверяет обработчик

Из локальных подсказок выбираются не более трех издателей в 10км. Прямая опубликованная ссылка контактов проверяется первой. С обычного website переход возможен только по фактически опубликованной навигации "Контакты" или "Как добраться", без угадывания адресов

Новый parser поддерживает наблюденные ограниченные `.t195__text` блоки. В одном блоке должны находиться указание "Приписные храмы", полное имя конкретного здания, его собственная подписанная DMS пара и населенный пункт. Независимая исходная точка выбранного OSM объекта должна находиться не далее 150м. Телефон - дополнительная проверка согласованности, а не доказательство здания

Результат - только INSUFFICIENT кандидат с происхождением, source URL/SHA и geometry URL/SHA. Он не получает автоматический binding, USER_CONFIRMED или разрешение пропускать чужие изображения. Сериализованная metadata не становится свежим свидетельством для foreign-image exception

Названия проверяются полно и строго. Общий текст про икону Богородицы без ее названия, разные типы/посвящения/нижний и верхний храм, дополнительный building heading или два семантически одинаковых child blocks не дают подтверждения. Неоднозначность проверяется до отбрасывания поврежденной геометрии

## Проверки

- Реальный ordinary OSM way226509018 с пустыми website/city/address/phone -> опубликованный собственный child heading и DMS point в 19.75м -> один canConfirm candidate. Исходный выбранный объект не меняется
- 21 JVM метод: source SHA, роли seeds и exact URL provenance, стабильный id, новая проверка следующей попытки, именованные и generic иконы, geometry/DMS/Unicode case/hemisphere/ranges, дубли/чужой heading, redirects/tenant paths, failed requests/deadline/2 workers, dismissal и serialized metadata
- Полный прогон: 1696 проверок, 0 ошибок, 1 прежний opt-in пропуск. Основная и тестовая APK собраны
- Реальные parent point в 4.71км и chapel point в 3.44км остаются отрицательными. Нельзя заимствовать координаты первого здания страницы
- Пять HTML fixtures и oracle неизменны. Дополнительные контакты Николая/Владимира в Воронеже и Воинского храма в Казани не имеют этой child-DMS структуры и не считаются новым охватом

Независимое Astra review выявило три дефекта: второй qualifier-first heading мог отдать точку первому, синонимичный invalid duplicate терялся до uniqueness, generic Marian title проходил как полный. После единственной implementer correction root исправил регрессию названия перед словом "иконы" и Unicode case русских labels. Все исходные и новые контрпримеры закреплены; итоговый static PASS и полный runtime PASS раздельны

## Бюджет и границы

Один pool attempt: максимум 60 локальных hints, 3 publisher scopes, 6 bounded fetch dispatches, 25с с учетом подготовки/очереди и 2 одновременно ожидаемых transport calls. Существующий transport может внутри dispatch сделать HTTPS/HTTP попытки и до двух redirects: это не обещание шести фактических HTTP GET

Новый класс пока получает typed seeds через dependency. Asset/catalog readers, быстрый composition с нынешними maps и fresh process-only witness не подключены. Реальный Android OCR/import/book/offline E2E этого нового источника не выполнен. Старые data safety/withdrawal guards не изменены

Нужно завершить: ordinary OSM -> local source pool -> fresh contact candidate -> существующее явное подтверждение -> конкретная датированная публикация -> соответствующая книга -> повторное открытие без сети. Не считать этот путь закрытым только по успешному parser/canConfirm
