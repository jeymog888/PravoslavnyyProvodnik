# Повторная проверка известного храма

Android-диагностика `LiveSealedHoldout12Test` принимает необязательный `holdoutKnownIndex` для одного уже изученного случая из групп 1-3. Исходный порядок и состав полной группы из 20 храмов сохраняются, если параметр отсутствует

Для групп 4-5 выбор отдельного случая запрещен до чтения входных данных и сети. Индекс должен быть каноническим числом 0-99 и принадлежать выбранной группе. Новый набор из трех Android-проверок подтверждает эти условия, включая отказ до обращения к неизвестной группе

Одиночный запуск записывает `KNOWN_DEVELOPMENT_CASE`, `selectedDenominator=1`, исходный `fixedBatchSize=20` и выбранный индекс. Он помогает воспроизвести конкретный дефект, но не измеряет независимое покрытие расписаний. `applicationSuccess=false` сохраняется до отдельной сверки с опубликованным источником: успешное исполнение проверки и статус READY сами по себе не подтверждают правильность служб

Проверено: 3/3 Android-проверки селектора, прежние 27 проверок обычного повторного обновления сохранены. Диагностический путь применен для поиска потери актуального изображения и ошибки OCR в известном случае 021. Эти ошибки не объявлены исправленными только на основании успешного исполнения диагностики
