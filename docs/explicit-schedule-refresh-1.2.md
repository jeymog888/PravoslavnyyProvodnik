# Повторное получение расписания и полный Main путь в 1.2

## Исправленная причина

Кнопка "Обновить расписание" раньше создавала intent поиска альтернативных сайтов. При пустом результате fallback мог снова закончиться предварительным Map предложением, не запуская полный поиск источника. Следующая попытка с сохраненным Map также могла остаться проверкой метаданных

Теперь обычное обновление снимает manual-search intent и выполняет настоящий refresh. "Искать другие сайты" - отдельное вторичное действие только в подходящем неподтвержденном состоянии. Кнопка без обработчика не подменяется обычным обновлением

Предварительный быстрый поиск может остановить cold попытку на предложении. Завершенная повторная попытка проходит дальше к общему resolver. При отклоненных или конфликтующих предложениях сохранен обход, который учитывает эти исключения, чтобы прежнее Own A не скрывало допустимое Own B. Подтверждение сайта, конфликты, отмены, CAS и проверка источника не ослаблены

## Реальный пользовательский путь

`main-refresh-616cc2d0`, новый отдельный профиль Android35, production MainActivity/AppContainer, настоящая сеть. Ввод "Вознесения Калуга" -> точный OSM way155168069 без записанного сайта -> обычное UI обновление -> PUBLISHER_GEOMETRY_CHAIN/t20385 -> расписание выбранного храма -> опубликованная литургия 15 ноября 2026 в07:00 -> книга литургии с ключом `2026-11-15|LITURGY|10|~|~`

Один тест завершился PASS за46.742s. Это время всего сценария с обновлением, открытием текста, переключениями и проверками, не замер поиска за20s. Пять распознанных событий опубликованы на странице источника; год восстановлен существующим ограниченным правилом и пометка об этом сохранена. Raw HTML этого конкретного UI прогона отдельно не записан, прежний host diagnostic не выдается за его byte oracle

Фактическая выбранная служба имеет одну часть. Ее точная версия сохранена на диске: 637 блоков, 436 молитв с переводом. Это количество блоков, не процент русского перевода. Подготовка лишних служб не выполнялась. Оригинал, Русский и временное объяснение "Смысл" оставляют прежний BLOCK anchor и fraction0.576

## Физическая проверка без сети

После первого холодного запуска обычная кнопка "Продолжить чтение" восстановила ту же версию и тот же курсор. Без сети проверены Русский -> Смысл -> К тексту -> Оригинал. Объяснение показывает фрагмент из открытой строки; режим чтения и положение не теряются

Отдельный строгий цикл: живой PID8891 -> force-stop только собственного QA приложения -> отсутствие PID -> новый production PID10051 -> обычный UI Resume -> та же exact edition SHA и полный durable cursor. Текущий default network отсутствует и Current Networks пусты как до перезапуска, так и после показа текста. Исходные airplane/wifi/mobile data восстановлены

Первая попытка этого строгого цикла остановилась из-за неверного предположения тестового обхода, что одного свайпа достаточно для кнопки Resume. FAIL и PNG сохранены. Отдельный исправленный обход ищет реально видимую кнопку максимум четырьмя свайпами, использовал два. Текст или положение для успеха не подставлялись

Еще15 отдельных контролируемых native сценариев прошли: частичный отказ сети и дозагрузка, ошибка локального чтения, exact edition поиска, отказ записи курсора, отмена поиска, сохранение места при Смысле и переходах к микрофону. Это не проверка точности реального ASR
