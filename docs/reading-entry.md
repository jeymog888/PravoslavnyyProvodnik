# Вход в службу и дата чтения

Карточки текущей и следующей службы независимы. Нажатие "Смотреть службу" передает конкретный ContextSuggestion в ServiceEntryResolver и получает свежий расчет по часам самого действия. Совпасть должны храм, полный Instant начала, источник, канонический часовой пояс и дата. Переход next -> current допустим; другая служба не подставляется при устаревании выбора

Будущая служба открывает подготовку на паузе. Текущая открывает начало доступного текста предполагаемого этапа, тоже на паузе. Расписание определяет только приблизительный этап, не строку, которую сейчас произносят

ReadingContext содержит принятую дату, храм, зону, источник и необязательное начало. Полночь не меняет дату уже открытого текста. Ручное уточнение и переход по порядку сохраняют контекст. Новое ручное чтение получает текущую дату храма. Поиск в новом ручном входе использует эту дату, даже если отдельно сохранено чтение будущей службы

ReadingAcceptanceStore принимает context, ServiceSession, stage_id и нужное удаление старых bookmarks одним SharedPreferences.Editor. При commit=false Android уже может изменить память. Поэтому сохраняется снимок только затронутых ключей и выполняется одна попытка вернуть старый набор. UI принимает новую позицию только при успехе. Rollback не гарантирует запись на неисправный диск и не повторяется бесконечно; темп, язык, тема, храм и прочие несвязанные настройки не откатываются

Сохранения 0.4 не содержат исходной даты службы. Для валидной старой session дата текстов выводится из времени сохраненного anchor в зоне храма - это миграционное допущение, а не восстановленная дата фактической службы. Оно применяется и при восстановлении прямо в экран чтения. Если валидного anchor нет, сохраненный этап можно явно открыть на сегодня; это подписано на главной. Поврежденная или принадлежащая другому храму metadata не превращается молча в сегодняшнюю дату: приложение возвращает к явному выбору

Новый контекст имеет строгую версионированную схему, проверяет типы, даты, зону, происхождение и неоднозначные DST-времена. Сохраненный startEpochMillis точен до миллисекунды; сопоставление карточки происходит по полному исходному Instant до округления

До интеграции единого плеера этот слой использует ServiceSession для совместимости. Он не открывает микрофон и не запускает автоматическое движение
