# Продолжение поиска после первого найденного сайта

После нового сетевого поиска на карте приложение показывает найденные сайты и само выполняет одну ограниченную попытку найти дополнительные приходские источники. Читателю не нужно отдельно запускать второй поиск. Статус и действие "Проверить сайты" остаются на месте при завершении или частичной ошибке

Переходы "Служба"/"Мой храм" для просмотра сохраняют ту же попытку. Выбор другого храма, изменение даты, настройки, открытие книги, внешнего сайта, уход приложения в фон и другие управляющие действия отзывают ее. Поздний ответ не получает нового права продолжать поиск

Это поиск источников, не автоматическое подтверждение их принадлежности храму и не подстановка времени службы. Найденный сайт проходит прежние проверки и явный выбор. Сохраненное расписание, отмены и подтвержденные источники не заменяются новым списком кандидатов

## Границы реализации

Одна попытка доступна только после свежего результата фактического Map provider, записи и перечитывания точного состояния. Cache/восстановление, сторонний provider без поддержки нового контракта и повторная доставка не создают право. Новое независимое cold HTTP после recreation имеет отдельное право, старое не оживает

Own поиск сохраняет пределы 25 секунд, 6 запросов, 3 издателя, 2 параллельных обращения внутри общего 35-секундного ограничения. Изменяются только разрешенные поля metadata. Финальная запись и отзыв права разделяют общий lock/CAS. На новом экране нужен собственный настоящий draw и следующий кадр перед стартом

Порядок уже показанных сайтов стабилен; новые дополняют список. Изменение только времени проверки не перемещает кнопку под пальцем. Полные актуальные proof/owner guards и повторное подтверждение источника сохранены

- Совместная JVM группа: 692/0/0, включая все 621 проверки расписаний/epoch и профильные проверки чтения. Debug/androidTest build PASS
- Native 41: 62 PASS, 8 FAIL, 0 SKIP. Прежние manual8, timestamp4 и source-review14 прошли на том же production APK. Ошибки относятся к двум новым тестовым сценариям в четырех конфигурациях
- Native 42 после независимого review test-only исправлений: все 44 automatic scenarios PASS. Production APK и все десять production payloads побайтно прежние. Все 70 уникальных проверяемых условий пройдены между этими двумя запусками; единый native41 прогон не переименован в зеленый
- Исправлены измерение незаполненной paragraph width и неверная попытка удержать часы через physical click: библиотека сама продвигает время touch events. Controlled handoff теперь проверяет настоящий VIEW callback одним UI turn, точное равенство часов, ноль запросов до собственного кадра нового экрана, затем ровно одну попытку. Проверки физического нажатия сохранены отдельно
- Четыре свежие handoff квитанции независимо перечитаны root. Все 68 исходных защищенных файлов совпали после обоих запусков. Просмотрены свежие PNG обеих тем и экранов на constrained320dp/fontScale2 harness

Первый JVM negative ошибочно менял телефон вместо identity. Existing fingerprint не включает телефон; тест теперь меняет адрес и проверяет, что fingerprint действительно другой. Production identity policy не менялась
