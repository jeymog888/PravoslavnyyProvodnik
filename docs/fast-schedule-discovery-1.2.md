# Источник расписания раньше тяжелого поиска

Порция 1.2.0-dev. Это ускорение доступности найденного предложения, не увеличение доказанного покрытия расписаний

## Изменение

У обычного OSM храма без настроенного сайта сначала проверяется ссылка на его точном объекте карты. Если она есть, сохраняется прежний автоматический EXACT_MAP_LINK. Иначе официальная карта и "Елицы" вызываются до длинной цепочки справочников. При свежем пригодном кандидате поиск завершается и становится доступно существующее действие "Это расписание моего храма"

Предложение не получает статус подтвержденного сайта или готового расписания. Сайт импортируется после явного подтверждения с новой проверкой. Отклоненные, конфликтующие и непригодные предложения не останавливают прежний поиск

Действующие публикации, ручной сайт, пользовательское подтверждение, отмены и повторная проверка дочернего здания сохраняют прежний маршрут. Поздний результат не переписывает более новую смену сайта, отказ или отмену. Исходный OSM ответ и выдача поставщиков повторно используются только внутри текущей попытки, с учетом выбранной идентичности и исключенных URL

## Границы времени

Один начальный OSM запрос ограничен 3с. Штатные поставщики имеют 25с, Composite - максимум 30с, внешняя защита - 35с. Внешний лимит оставляет время сохранить уже готовую ветку при timeout другой. Это не обещание результата за 20с на любом храме

Если пригодных кандидатов нет, прежний автоматический маршрут получает две дополнительные начальные попытки к картам. Их не скрываем как прежнее количество запросов: отдельные integration assertions требуют ровно один Map и один Elitsy GET, затем прежние proof/import цепочки 5/3/17 запросов. Бюджеты и корректность самого сильного доказательства сохранены, но такая перестановка может добавить ожидание перед старым успешным fallback

Все три refresh завершились до тяжелой цепочки и без импорта сайта. 21/21 реальных HTTP ответа - 200 с полным сохраненным body; каждый case сделал 7 запросов. Пределы не исчерпаны, соединения закрылись. Проверка включает диагностическую паузу между запросами и поэтому не является чистым измерением скорости APK

Это ранее положительные объекты из frozen100, отобранные для повторной диагностики порядка, а не новая слепая выборка. Никакой из трех сайтов здесь не подтверждался, события не импортировались, книги не загружались. Показатель готовых датированных расписаний этой проверкой не измерен

Исходники/compiled classes перенесены в отдельный неизменяемый capsule, собран только probe. Проверены actual timezone классы, Gson2.10.1, неизменность исходных результатов frozen100, классов, исходников и библиотек. `sealPassed=true`, hardTimeout=false. Пользовательские данные не читались
