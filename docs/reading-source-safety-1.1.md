# Принятие текста и старые молитвы в 1.1

## Сохраненное место

Выбор посвящения переносит место только из точной прежней книги в точную новую книгу, проверенную на диске. Известные пропуски храмового тропаря и кондака переходят к опубликованному песнопению. Неизмененный абзац сохраняет положение, неизвестное соответствие возвращает к началу раздела

Существующее принятое место новой книги важнее первоначального переноса. Сравнивается полный typed snapshot, а не один hash. Предыдущая книга не нужна для повторного открытия уже принятой новой книги

Запись позиции, last и receipt подготовки атомарна. Receipt переживает вытеснение обычного индекса из 32 позиций. Если указатель пропал, наличие receipt останавливает повторный перенос и загрузку latest. При лимите 128 receipts новая подготовка отклоняется, старое доказательство не удаляется. Ошибки диска откатывают все связанные значения

Возврат сохраняет текущий прогресс новой книги, уважает более свежую принятую позицию старой и восстанавливает исходный snapshot только при Absent. Проверка актуального экрана выполняется вызывающим интерфейсом непосредственно перед синхронной записью

## Молитва и подпись

В двух настоящих сохраненных книгах найдены 3 + 7 молитв с точным префиксом "И священник возглашает:". Старый формат называл их RUBRIC и копировал оригинал в russian. Read-only helper распознает только public MATINS/VESPERS с этим литералом и непустым телом

ID, hash, полный оригинал и UTF-16 координаты остаются прежними. Для темпа используются слова молитвы без подписи. Новые результаты поиска обозначают исходный язык. Старые RUSSIAN pending targets совместимы с полным неизмененным текстом. Непереведенная молитва прерывает заимствование русского контекста из более раннего прошения

Отдельный DOM-профиль исправляет четыре доказанных цельных отпуста из опубликованного HTML. Частичный отпуст с незаполненным посвящением, другие подписи и алтарный текст этим правилом не изменяются. Старые принятые книги автоматически не переписываются

Второй узкий профиль исправляет две дословно проверенные доксологии, которые HTML-repair оставил в прямых i-узлах между подписанными песнопениями. Требуются public MATINS/VESPERS, div.variable_text, единственный TextNode, точная raw-строка и оба непосредственных p с прямыми source labels. Пропускаются только whitespace-узлы. Текст, порядок, нормальные вложенные i и подписи сохраняются

## Проверка

- Полный JVM-набор интеграции: 1387 тестов, 0 failures/errors, один прежний skip. Затем все 14 тестов переноса/возврата прошли отдельно, включая добавленный behavioral daily-variant case
- Семь тестов старого presentation, семь atomic cursor/receipt и три DOM-сценария проверяют настоящие архивы, конкурентное изменение, rollback и отрицательные границы. До исправления отдельно воспроизведены две поисковые ошибки
- Истинные Android-архивы имеют иной порядок сериализации полей, чем desktop JVM. JVM проверяет их неизменный declared hash через исходное JSON-дерево с сохраненным порядком, без перехеширования книги. Настоящие production integrity и FileBookCache дополнительно прошли на Android с этими же байтами
- Независимое Astra-ревью нашло повторный перенос после утраты уже принятого указателя. Исправление receipt повторно проверено; новых P1/P2 в финальном domain-коде не найдено
- Для доксологий baseline 7 тестов воспроизвел ровно два ожидаемых позитивных провала. После узкой правки 38 целевых тестов проходят, включая прежний parser, отпуст, source contract и настоящие части вечерней службы. Дополнительные отрицательные проверки soft hyphen и лишнего пробела добавлены после baseline. Astra повторно прочитала код и итоговые XML, блокирующих замечаний нет

Это проверка основы. Результаты полного интерфейса, настоящей загрузки и финального APK записываются отдельно
