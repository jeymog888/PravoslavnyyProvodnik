# Первая случайная проверка расписаний 1.2

Базовый результат 14 ноября 2026: в заранее закрепленном первом батче из 20 объектов не получено ни одной пригодной публикации. До загрузки книги этот сетевой прогон не дошел. Это незакрытая продуктовая проверка, а не доказательство отсутствия расписаний у храмов

Выборка содержит 10 объектов с сайтом в каталоге и 10 без сайта. Исходный набор из 100 объектов, порядок и группы не менялись. Остальные 80 остаются NOT_RUN. По этому сбалансированному батчу нельзя публиковать общий процент покрытия российских храмов. Действующий статус объектов тоже не проверен: могилы и руины не исключались после получения результата

## Что проверено

Настоящие Android HTTP GET/POST, PDF/OCR и source repository с теми же параметрами транспорта, хранилища и resolver factories. Книги подключены через production AppContainer, но ни одна не была запрошена из-за отсутствия принятой публикации

Native51 завершил все 20 случаев. JUnit1/1 и invariants PASS означают завершение и сохранность данных. Они не означают успех приложения: applicationSuccess остается false, primarySourceOracle - NOT_REVIEWED. Все 68 прежних файлов пользователя сохранены побайтно

Независимый actual Astra audit сверил 31 source pin, 20 case reports и 173 SHA сохраненных HTTP bodies. Ошибка harness, скрывающая готовые publication объекты, не найдена: publication=null во всех 20 конечных состояниях и 28 записанных действиях

Протокол передает выбранный Parish напрямую и использует отдельные owned preferences. Он не проверяет поиск по имени/GPS, человеческие 20 секунд, восстановление выбора в Main или физический перезапуск. UI continuation заменена одним разрешенным explicit source search. Нужны отдельные Main sentinel и cold resume

## Что показал разбор

- Нулевая публикация не равна отсутствию данных: [текущая публикация храма](https://www.bcex.ru/raspisanie-bogosluzheniy-411) уже доступна по прямой ссылке с главной страницы. FIFO тратит лимит HTML на общие индексы раньше нее. Следующая порция проверяет общий приоритет service-schedule links при прежних лимитах и прежних проверках даты/храма/отмен
- В некоторых страницах есть свежие подписи рядом со старыми URL или таблицы без года. Нельзя назначать им 2026 только ради успешной метрики. Требуется отдельное доказательство периода и принадлежности строк нужному зданию
- Known website запрещает текущий alternate metadata search. У части объектов без сайта теряется полезный locality/contacts context, хотя точный near-point профиль уже прочитан
- OwnContact pool сейчас ограничен небольшим набором seeds и одним форматом приписных храмов. Его нельзя описывать как общий поиск источников всех приходов

Первый батч теперь является материалом для исправления общих механизмов. Новая независимая проверка после фиксации изменений должна использовать следующий ранее закрепленный батч. Старые отрицательные результаты сохраняются
