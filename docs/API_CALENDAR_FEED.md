# Календарное дополнение Азбуки для Феории 0.9

API дает контекст церковного дня и опубликованные тексты. Оно не определяет расписание конкретного храма и не задает порядок службы. Полное последование продолжает загружаться с `azbyka.ru/worships/`, чтения - из проверенного библейского источника. Эта граница сохраняет выбранную дату, службу и вариант последования

Страница API описывает интеграцию календаря на сторонние сайты и регистрацию пользователя API. Это не основание распространять весь массив ответов. Адаптер выдает только небольшой пакет на конкретную дату, без учетных данных, изображений, аудио, полных житий и произвольных API-полей. У каждого текста сохраняется ссылка на календарь Азбуки. Никакая отдельная лицензия или одобрение массового зеркалирования здесь не предполагается

## Что получает телефон

Адрес пакета:

`https://raw.githubusercontent.com/jeymog888/PravoslavnyyProvodnik/calendar-cache/days/YYYY-MM-DD.json`

Схема версии 1:

- `date`, `sourceUrl` - строго одна и та же дата календаря
- `weekTitle`, `voice` - название седмицы/дня и глас, если он указан
- `commemorations` - названия памятей в порядке `day.paragraph`, `day.number`; короткие опубликованные описания при наличии
- `translations` - точная пара `original`, `russian`, с `sourceTitle`, `sourceUrl`, `apiId`
- `generatedAt` - время подготовки пакета в UTC

Максимум 100 памятей, 200 переводов и 512000 байт на пакет. Превышение любого предела отклоняет пакет целиком. Тексты очищены от HTML, активных элементов и управляющих символов. Заголовки, даты и источники проверяются при генерации и повторно в приложении

`explanation` из API не считается переводом по имени поля. Пара принимается только при совпадении всего оригинала и всего перевода с фрагментом, явно названным "Перевод" на публичной странице той же даты. Снятие ударений и пунктуации не меняет слова и не использует приблизительный поиск. В частности, `й` не превращается в `и`

Если один оригинал имеет несколько разных подтвержденных переводов, адаптер исключает этот неоднозначный оригинал целиком, сохраняя остальные пары и контекст дня. Он не выбирает первый вариант и не превращает один спорный фрагмент в отказ всего дня

Сам пакет не задает порядок песнопений. Приложение использует перевод только при точном совпадении с оригиналом уже выбранного последования. На Рождество API также вернул песнопения среды, отсутствующие в праздничном последовании - этот случай есть в регрессионном тесте

Короткое описание памяти не является объяснением произвольного фрагмента службы. Если описания нет, адаптер не сочиняет его. Богослужебные указания, полные жития и чтения из дополнительных API-текстов не включены в эту небольшую схему. Проверенные дополнительные чтения оказались ссылками на стихи, а не самими стихами

## Как используется в приложении

При загрузке книги Android запрашивает пакет ее богослужебной даты. Календарные переводы дополняют только точные совпадения оригинала в уже выбранном последовании. Отсутствие пакета не меняет дату, вид службы или ее порядок и не препятствует использованию других источников текста

Контекст открывается по кнопке "О церковном дне" в режиме "Смысл" у начала книги или в сведениях об источниках. Седмица, глас и памяти находятся в отдельном окне, вне ленты молитв. Короткие описания берутся из опубликованных данных; пояснения глав службы остаются отдельной редакционной работой Феории

Полученный контекст и точные переводы сохраняются вместе с принятой редакцией книги на телефоне. Ее повторное открытие не требует обращения к API или GitHub. Уже сохраненная книга не заменяется новой редакцией без подтверждения пользователя

## Обновление и отказоустойчивость

Workflow запускается только с `main` в репозитории проекта: ежедневно и вручную. Он готовит сегодняшнюю дату по Москве и семь следующих. Это дополнительный источник, а не единственный путь чтения: для других дат или при отсутствии пакета работает прямой загрузчик опубликованных текстов. Отсутствие календарного дополнения не означает отсутствие службы

За запуск разрешено не более 14 дат, 500 HTTP-запросов и одного запроса одновременно, с паузой 0.7 секунды между началами запросов. Повторные обращения к одной сущности в рамках запуска используют память. Недавние проверенные пакеты повторно используются 24 часа. Публичные страницы календаря получают запросы без Authorization. Запросы с токеном идут только на разрешенные маршруты `https://azbyka.ru/days/api-v2/`; перенаправления запрещены

Каждый файл записывается атомарно после полной проверки. Весь пакет публикации проверяется до обновления ветки. При ошибке API, неверном формате, исчерпании лимита или конфликте публикации прежняя удаленная версия остается. Временные локальные успешные файлы не публикуются, если последующая дата завершилась ошибкой. Force push не используется

Публикатор читает только Git-объекты с датированными JSON и отдельным зашифрованным состоянием токена из `calendar-cache`, не делает checkout этой ветки и не запускает из нее код. Он сохраняет предыдущие проверенные файлы за 400 дней, ограничивает общее количество 1000 и публикует дерево `days/` и необязательный `token.enc.json`. Неожиданные файлы, симлинки и исполняемые файлы отклоняются. Офлайн-копии уже открытых книг хранятся отдельно на телефоне и не зависят от срока хранения публичного дополнения

## Доступ и срок токена

Пароль не нужен адаптеру и не хранится. Токен передается только через настроенный защищенный секрет `AZBYKA_API_TOKEN` или приватный локальный JSON-файл `--token-file`. Открытый JWT не входит в аргументы командной строки, APK, публичные пакеты, сообщения об ошибках и Git. В ветке публикации хранится только его зашифрованное состояние, описанное ниже

Живой сервер обновления токена отличается от примера OpenAPI: для `POST token/refresh` нужны и тело `{token: ...}`, и заголовок Bearer с тем же токеном. В двух живых проверках исходный JWT оставался действительным после обновления. Полученные JWT действовали 31 день. Обновление в памяти без сохранения нового токена не решает последующие запуски

С `--token-state` перед загрузкой данных адаптер расшифровывает последнее состояние, обновляет JWT и проверяет новый ключ настоящим запросом `daytype`. После успешной подготовки всех дат он сохраняет только зашифрованный envelope. Данные и envelope публикуются одним коммитом. При отмене, сетевой ошибке или ошибке проверки прежняя удаленная версия и ее токен сохраняются

Для шифрования используется [Fernet из cryptography](https://cryptography.io/en/latest/fernet/) с проверкой подлинности. Ключ выводится HKDF-SHA256 из исходного JWT и случайной соли, с отдельным контекстом Феории. Публичный envelope содержит только версию формата, алгоритм, соль и шифротекст. В нем нет открытого токена, почты, payload JWT или других учетных сведений. Размер ограничен, неизвестные поля запрещены; неправильный ключ или повреждение приводят к отказу без обхода проверки

Исходный JWT в `AZBYKA_API_TOKEN` становится постоянным материалом ключа шифрования. Его нельзя раскрывать даже после окончания срока действия в API. Менять этот секрет в одиночку нельзя: старый envelope перестанет расшифровываться. Для плановой смены нужен проверенный новый JWT и согласованное пересоздание зашифрованного состояния владельцем проекта. Пароль и административный GitHub PAT для ротации не используются

Это не обещание бессрочной доступности: отзыв доступа Азбукой, отключение workflow или перерыв дольше срока последнего JWT могут потребовать нового входа владельца. Реальное обновление и повторный запуск с расшифрованным состоянием проверены в указанных выше успешных запусках. Тест с искусственно истекшим master проверяет криптографическую механику, а не способность сервера принять просроченный JWT

## Локальная проверка

Из корня репозитория:

```sh
python3 -m pip install -r scripts/calendar_feed/requirements.txt
python3 -B -m unittest discover -s scripts/calendar_feed/tests -p 'test_*.py'
python3 -B scripts/calendar_feed/generate.py --token-file .local/azbyka09/token.json --out .local/azbyka09/feed/days --date 2026-11-11 --date 2026-11-12
```

Последняя команда выполняет реальные запросы, поэтому ее запускает владелец локального доступа. Пароль и значение токена в команду подставлять не нужно

Для отдельной проверки ротации добавляется `--token-state .local/azbyka09/feed/token.enc.json`. Первый запуск создает envelope, второй должен прочитать его и обновить JWT снова. Ключ и расшифрованный токен не выводятся

Offline тесты проверяют пять выборок реальных дат, несовпадение оригинала/перевода, чужую дату, отсутствие перевода, тип гласа, очищение HTML, границы данных, сетевой бюджет, отсутствие Authorization на публичной странице, отказ перенаправлений, безопасные ошибки, сохранность предыдущей версии и гонку публикаций. Отдельно проверяются подмена/повреждение envelope, неправильный ключ, случайность шифротекста, отсутствие открытых секретов, отмена между обновлением JWT и публикацией, обновление при полностью свежем кэше и совместная публикация данных с зашифрованным состоянием. Git-проверки работают только в новых временных репозиториях, не меняя проектный Git

Прохождение этих тестов не доказывает живую доступность API, доставку опубликованного файла в Android или чтение после перезапуска без сети. Эти сценарии входят в отдельную приемку приложения
