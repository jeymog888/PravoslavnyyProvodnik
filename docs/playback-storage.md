# Сохранение единого плеера

Этап 3.2a добавляет хранилище и миграцию, без подключения к MainActivity или экрану чтения

`StoredServicePlayback` содержит `ReadingContext` и `ServicePlaybackSnapshot`. Ключ - `service_playback_v1`. Формат ограничен 8192 символами, имеет свою версию и строго проверяет типы, обязательные поля, дубликаты, целые числа, enum и стандартную JSON-лексику. Контекст хранится строкой своего отдельного версионированного codec, поэтому его даты, зона и источник проходят те же проверки, что при входе

`ServicePlaybackStore.restore(plan, expectedContext)` возвращает одно из трех состояний:

- `Absent` - ключа действительно нет, можно рассмотреть однократную миграцию
- `Valid(stored, state)` - контекст совпал, план и позиция проверены, state всегда paused
- `Invalid(reason)` - чтение prefs, формат, контекст либо план несовместимы. Это не повод импортировать старую позицию снова

В snapshot нет playing и монотонного timestamp. Индекс сегмента допустим только вместе с совпавшими версией и fingerprint; changed content не использует старый индекс

## Принятие позиции

`ReadingAcceptanceStore.acceptPlayback(plan, context, snapshot, marker, resetBookmarks, bookmark?)` принимает уже материализованный snapshot. Контроллер сам выбирает один монотонный timestamp для действия и получает snapshot через engine

Дата контекста должна совпасть с планом. Marker должен иметь этап snapshot, `autoAdvance=false`, `elapsedInStageMillis=0`. Он служит совместимой отметкой, собственное время больше не задает

Контекст, marker, stage_id, snapshot и необязательная текущая закладка записываются одним Editor. При ошибке записи выполняется одна попытка отката только затронутых ключей. Обязательную runtime-паузу контроллер сохраняет даже при ошибке диска

`PlaybackBookmark.at(plan, state)` выводит адрес текущей или retained строки. Переданная в acceptPlayback закладка должна соответствовать именно этому адресу. Для нее записываются старые track/line/phrase keys, offset сбрасывается в ноль, saved_tempo удаляется. Остальные треки и глобальные настройки не меняются

При новом чтении reset удаляет старые закладки перед записью новой начальной закладки. Это важно: обратный порядок удалил бы начальную позицию тем же Editor. Регрессия покрыта отдельным тестом

Старый `accept` сохранен для текущего неподключенного UI. Если новый snapshot уже существует, старый вход удаляет его в той же транзакции, чтобы не оставить позицию другого чтения. Интегрированный плеер должен использовать acceptPlayback

## Миграция и ручной выбор текста

`LegacyPlaybackMigration.resolve(plan, stageId, values)` ничего не записывает. Любое присутствие нового ключа, включая поврежденный, запрещает миграцию. Неизвестный этап возвращает null. Сохраненный track ищется только в выбранном этапе; отсутствующий или чужой ID ведет к началу доступного текста этого этапа

Phrase ID ищется внутри выбранного track. Только отсутствие phrase key позволяет использовать старый Int index. Присутствующий, но исчезнувший или неверного типа ID ведет к первой строке. Некорректный индекс также ведет к началу. Offset старого таймера не переносится, скорость NORMAL, состояние paused

`PlaybackBookmarks.forTrack(plan, trackId, values)` использует ту же адресную логику для ручного возвращения к другому тексту после миграции. Он доступен и при существующем новом snapshot. Глобальные язык, тема, размер текста и закладки других треков сохраняются

Старые Scripture ID включают дату и содержание. Закладка другого дня не может выбрать текст, которого нет в плане принятой даты

Проверки покрывают строгий формат, отличие absent/invalid, контекст и changed content, cold paused restore, адресную миграцию, reset и rollback нового ключа, недопустимые markers, повторную ошибку диска и несвязанные изменения prefs
