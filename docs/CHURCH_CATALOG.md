# Offline-каталог храмов

`scripts/church_catalog/import_catalog.py` собирает компактный JSON из локального снимка OpenStreetMap, например официального `.osm.pbf` Geofabrik. Скрипт не скачивает данные, не вызывает геокодер и не публикует результат

## Включенный снимок

`app/src/main/assets/discovery/churches-ru.json` содержит 13 493 явно православных объекта из российского снимка Geofabrik на `2026-11-10T21:21:39Z`. Это 11 604 храма, 1 531 часовня и 358 монастырских объектов. Разные здания и монастырь целиком сохраняют разные OSM ID

- Исходный PBF: 4 202 162 536 байт, SHA-256 `2de4773b79e04fe66f0ef058b687a98902468d094bb62cb88214f800bd65fa19`
- Готовый JSON: 8 005 037 байт, SHA-256 `0f247acbefe335313885a17c308db828ece60fabe29ec78fa9f9bf24e718d200`
- Все 142 908 запрошенных nodes и 15 632 ways прочитаны, объектов с отклоненной геометрией нет
- Только у 2 271 записи явно указан город, у 1 095 есть допустимый сайт, включая 434 сайта HTTP. Пустое поле не заполняется догадкой

Это не все храмы страны, не подтверждение действующего прихода и не база расписаний. Поиск метро и городов пока использует сетевой источник. Название и координаты из каталога помогают выбрать храм; приходской сайт и даты служб проверяются отдельно

JSON является производной базой OpenStreetMap и распространяется на условиях ODbL 1.0 с сохраненной атрибуцией и ссылками на лицензию. Исходный PBF не включается в Git или APK; путь воспроизводимой сборки и закрепленная версия библиотеки приведены ниже

## Сборка

Нужен Python 3.9+ и отдельное окружение с закрепленной версией PyOsmium

```sh
python3 -m venv /private/tmp/feoria-church-catalog-venv
/private/tmp/feoria-church-catalog-venv/bin/python -m pip install -r scripts/church_catalog/requirements.txt
/private/tmp/feoria-church-catalog-venv/bin/python scripts/church_catalog/import_catalog.py \
  .local/church-catalog/russia-261110.osm.pbf \
  --source-url https://download.geofabrik.de/russia-261110.osm.pbf \
  --output .local/church-catalog/churches-v1.json \
  --report .local/church-catalog/import-report.json \
  --scratch-dir .local/church-catalog
```

Путь и `--source-url` должны указывать на один и тот же закрепленный снимок. Нельзя скачивать `latest`, а затем приписывать ему дату другого файла. Скрипт вычисляет SHA-256 самого входного файла. При повторной сборке можно передать этот хеш через `--expected-sha256`

Дата дампа берется из `osmosis_replication_timestamp` в заголовке. Если источник не содержит дату, нужен `--dump-timestamp` с подтвержденной датой источника, например `2026-11-10T21:00:00Z`. Это пример формата, не утверждение о дате российского дампа. Текущее время, время файловой системы и даты отдельных объектов не подставляются вместо даты снимка

По умолчанию включены только явно православные объекты. `--include-unconfirmed-christian` дополнительно включает объекты с `religion=christian` и отсутствующим или пустым `denomination`. Они всегда получают `kind=WORSHIP_PLACE` и `isChapel=false`: название или форма здания не подтверждают конфессию

Коды завершения:

- `0` - все подходящие объекты имеют полную геометрию, каталог и отчет записаны
- `2` - каталог записан, часть объектов исключена из-за неполной или невалидной геометрии; нужен просмотр `rejectedByReason` и `rejectionExamples` перед включением в приложение
- `1` - ошибка чтения, хеша, формата, лимитов или пустой результат; отчет содержит `status=failed`, предыдущий каталог до стадии записи не заменяется

JSON записывается через временный файл и атомарное переименование. В выходном каталоге нет текущего времени или абсолютных рабочих путей: одинаковый вход, имя входного файла, параметры и версия библиотеки дают одинаковые байты. Отчет содержит хеш готового каталога

## Отбор объектов

Фильтр согласован с `DiscoveryJson.churches`:

- `amenity=place_of_worship` или `amenity=monastery`
- `religion=christian`
- хотя бы один точный элемент списка `denomination`, разделенного `;`: `orthodox`, `russian_orthodox`, `greek_orthodox`, `serbian_orthodox`, `georgian_orthodox`
- исключен `tower:type=bell_tower`
- есть непустое корректное `name:ru` или `name`

Другие религии, отсутствующая религия и известная другая конфессия не попадают в каталог, даже если название похоже на православное. Регистр и написание тегов автоматически не исправляются

`name:ru` имеет приоритет над `name`. Дополнительные названия из `name`, `name:ru`, `alt_name`, `alt_name:ru`, `official_name`, `official_name:ru`, `short_name`, `short_name:ru` сохраняются в `aliases`. Уникальность определяется только полным идентификатором `osm:node:N`, `osm:way:N` или `osm:relation:N`. Совпадающие названия, координаты или числовые ID из разных пространств не объединяют здания

## Геометрия и ресурсы

Скрипт делает три прохода разбора OSM и отдельное последовательное чтение для SHA-256:

1. Нативный фильтр PyOsmium пропускает подходящие по amenity nodes/ways и все relations. Сохраняются только кандидаты и временная SQLite-таблица ссылок relations. Координаты всех nodes страны не индексируются
2. После раскрытия вложенных relations читаются только нужные ways и собираются ID их nodes
3. Читаются координаты только нужных nodes. Для way/relation вычисляется центр полного bounding box всех реальных членов, включая вложенные relations

Это центр границ геометрии, соответствующий смыслу Overpass `out center`, а не центроид, вход в храм или гарантированная точка внутри сложного полигона. Учитываются все роли членов relations, включая отдельные nodes. Разные части relation не заменяются центром города. Объекты с недостающим node, way или relation, невалидными координатами, пустой геометрией, коротким way или циклом relations исключаются целиком. Частичный bounding box не выдается за полный

Временная таблица relations ограничена 2 GiB и удаляется перед вторым проходом. По умолчанию сохраняется минимум 4 GiB свободного места; проверка идет между проходами и через каждые 10 000 relations. Ограничение на ссылки выбранной геометрии - 5 миллионов, на глубину вложения - 128. Достижение лимита вызывает явную ошибку, а не усечение каталога. Для маленьких тестовых файлов можно задать `--min-free-gib 0`. Параметры резервов нельзя уменьшать автоматически ради успешного отчета

Не используется `with_locations()` или полный location index. `BackReferenceWriter` здесь не применяется: для вложенных relations ему нужны дополнительные проходы по глубине. Используемые механизмы описаны в [документации фильтров PyOsmium](https://docs.osmcode.org/pyosmium/latest/user_manual/04-Working-with-Filters/) и [примере сбора зависимых объектов](https://docs.osmcode.org/pyosmium/latest/cookbooks/Filtering-Data-By-Tags/)

## Формат JSON

```json
{
  "schemaVersion": 1,
  "metadata": {
    "source": {
      "name": "OpenStreetMap via Geofabrik",
      "url": "https://download.geofabrik.de/russia-261110.osm.pbf",
      "fileName": "russia-261110.osm.pbf",
      "sizeBytes": 0,
      "sha256": "<64 lowercase hex characters calculated from the input>",
      "dumpTimestamp": "<source timestamp in ISO 8601 UTC>",
      "timestampOrigin": "osm_header",
      "license": "ODbL-1.0",
      "licenseUrl": "https://opendatacommons.org/licenses/odbl/1-0/",
      "attribution": "© OpenStreetMap contributors",
      "copyrightUrl": "https://www.openstreetmap.org/copyright"
    },
    "generator": {
      "name": "feoria-church-catalog",
      "version": "1.0.0",
      "osmiumVersion": "4.3.1",
      "includeUnconfirmedChristian": false
    },
    "recordCount": 0,
    "geometryRejected": 0
  },
  "churches": []
}
```

Это описание формы, не рабочий каталог и не доказательство количества объектов в дампе

Каждый объект `churches` содержит поля `DiscoveredChurch`: `id`, `name`, `center` (`latitude`, `longitude`), `address`, `city`, `region`, `country`, `website`, `isChapel`, `kind`, `sourceUrl`. Добавлены `aliases` и `sourceTags`

Адрес берется из `addr:full` либо из реально имеющихся `addr:city`, `addr:street`, `addr:housenumber`. Если города нет, улица остается улицей, а `city` остается пустым. `region` и `country` также заполняются только из адресных тегов. Административные границы, ближайшие города и обратное геокодирование не используются

`website` берется только из `website` или `contact:website`. Сохраняется явно опубликованный `http` или `https`; протокол не придумывается и не повышается автоматически. По правилам `ScheduleUrl.publicSource` исключаются userinfo, IP-адреса, локальные имена, нестандартные порты, пробелы, управляющие символы и неоднозначный URL. Некорректный сайт не удаляет сам храм. Валидность URL не подтверждает принадлежность сайта храму, наличие расписания или доверие к удаленному содержимому

`sourceTags` хранит исходные допустимые строки названий, религии, категории, контактов и `addr:*`. В том числе там может остаться исходный небезопасный `website` как свидетельство источника: UI и сетевой клиент должны использовать проверенное поле `website` и собственную валидацию, а не открывать произвольные значения `sourceTags`

Каталог включает атрибуцию `© OpenStreetMap contributors` и [лицензию ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/). При включении в приложение нужно сохранить эти сведения, доступную пользователю [атрибуцию OpenStreetMap](https://www.openstreetmap.org/copyright) и условия распространения производной базы. JSON и отчет не являются расписанием богослужений или подтверждением полноты OSM

## Проверка

```sh
/private/tmp/feoria-church-catalog-venv/bin/python -m unittest discover -s scripts/church_catalog/tests -v
```

Тесты используют только небольшие синтетические OSM XML и PBF: проверяют реальные координаты nodes, bbox ways, вложенные relations, пропуски и повреждения геометрии, циклы, пространства ID, разные здания с одинаковым названием, чужую религию, неподтвержденную конфессию, адрес без города, исходные контакты, безопасные URL, дату/хеш источника, воспроизводимость и сохранение предыдущего каталога при ошибке. Тестовые названия и координаты не предназначены для включения в приложение
