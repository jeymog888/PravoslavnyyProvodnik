# Проверка альтернативной русской OCR-модели

На одном сохраненном PNG 1448x2048 выполнено изолированное Android-сравнение текущей `tessdata_fast` и официальной [`tessdata_best`](https://github.com/tesseract-ocr/tessdata_best). Обе модели закреплены размером и SHA-256, модель best загружена по точному commit. Источник и лицензия сохранены отдельно, production модель и APK assets не менялись

Выполнен только начальный проход LSTM/PSM_AUTO с одинаковым bitmap, прежними ограничениями декодирования и настоящим parser. Дополнительные sparse-проходы не запускались. Это не приемка правильности расписания. Тест требует отдельного разрешенного параметра, уникальную принадлежащую диагностике папку, marker и точные исходные файлы; не пишет в настройки или сохраненные книги, не делает HTTP. При зависании root завершает только тестируемый процесс по внешнему пределу, такой запуск не считается успешным

Native76 завершился: fast распознавал изображение 962 мс, best 2301 мс. Обе модели дали те же 3 события с прежними пропусками и ошибкой границ названия. Замена модели не принята как решение: она не улучшила результат данного сценария. Размер best 15_301_764 bytes против 3_861_738 bytes текущей модели

Сохранены исходные hOCR с координатами, документы, результаты parser и квитанции обеих моделей. Это позволяет дальше проверять физические границы ячеек. После экспорта временная папка телефона удалена, все 68 защищенных пользовательских файлов неизменны. Улучшение покрытия храмов и полный успех приложения из этого эксперимента не следуют

Доказательства: .local/release12/schedule/ocr-model-comparison-draft/ASTRA.md/json, ocr-model-comparison-inputs/DOWNLOAD.json, integration/ocr-model-comparison/actual/ и integration/native-seventy-sixth/

## Отдельные физические ячейки

Native78 и Native79 проверили по 32 непересекающихся date/time crop одного исходного PNG, без изменения масштаба и без подсказанных ответов. Координаты заданы только диагностике, это не production данные

- BLOCK/BLOCK: 16 из 16 дат с днями недели и 13 из 18 напечатанных времен
- BLOCK/SPARSE: те же 16 дат и 15 из 18 времен, без новых неверных времен
- Оставшиеся три времени есть в исходном AUTO. Для одного нужны соседние фрагменты `8` и `:45`, подтвержденные координатами

Это основание для проверки безопасного объединения проходов, а не готовый импорт расписания. Условное покрытие 18 времен не доказывает правильность названий, календарных границ и выбора здания. При противоречии нельзя голосовать большинством. Production приемка должна отдельно получить точные события и названия через настоящий Android extractor

После экспорта собственные временные папки удалены, 68 исходных файлов основного профиля неизменны. Диагностика не делает HTTP и не меняет книги или настройки
