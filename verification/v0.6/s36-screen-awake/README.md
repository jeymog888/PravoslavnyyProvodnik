# Удержание экрана при активном чтении

Один владелец Activity Window включает только FLAG_KEEP_SCREEN_ON для видимого активного Text/Wait, включая уже запущенное ожидание начала. Потеря активности снимает флаг до сохранения паузы, старый callback не затрагивает нового владельца. Нет wake lock, фоновой службы или автоматического возобновления

Самопроверка исправила реальный дефект первоначального draft: первый attach теперь снимает и унаследованный флаг окна. Unit и UI проверяют этот случай. Root также исправил два устаревших test selector до запуска

Сборка s36-awake-r1: 440 unit и 9 UI PASS, inputs неизменны. APK SHA256 39cdad85d5d4f71a0fe1df6ca3c7d2f06df245951a9b3fd85923f8eb2b829ac6. Новые проверки читают настоящий Window flag, проверяют release-before-writer, неуспешный Play/pause, stale ownership, Text/Wait/BeforeStart/Meaning/Missing/End, темп и Settings

Нативная приемка при stay_on_while_plugged_in=0 и screen_off_timeout=15000: Text и Wait остаются Awake после 21 секунды без касаний, Pause и Home дают Asleep. Настоящий Recents лично просмотрен на PNG; возвращение к той же Activity и ручная блокировка оставляют плеер на паузе. Оба системных параметра восстановлены с readback

R1 сохраняется как FAIL подготовки драйвера, точная причина переходного foreground не доказана. R2 сохраняется как FAIL драйвера после успешных Text/Pause power-наблюдений: в wait_for был пропущен известный Taskbar. В R3 проверены только оставшиеся Wait/Home/Recents/lock, без повторного заявления Text PASS. R3 static gate PASS, динамические наблюдения хранятся отдельно. Исходные ошибки и обе исправленные версии драйвера сохранены

Root и независимый reviewer приняли код, тесты, реальные power-наблюдения и два PNG. Проверка выполнялась на эмуляторе API35, физический телефон не заявлен
