# Поиск храмов в Феории 0.6: проверка после обратной связи

Проверка: 9 ноября 2026, Europe/Moscow; сетевые записи содержат исходное время UTC 8 ноября 21:13-21:18
Роль: researcher, read-only. Исходники, тесты и устройство не менялись; Gradle/adb не запускались
База: ветка `codex/feoria-0.6-service-guidance`, текущая реализация поиска 0.5

## Вывод для решения

Замена надписи об ошибке недостаточна. В текущем продукте вообще нет внешнего поиска по названию храма: человек сначала ищет город, затем получает ограниченный список в радиусе 3 км от центра, затем фильтрует этот список. Сретенский монастырь как объект карты исключается запросом, потому что имеет `amenity=monastery`, а приложение принимает только `place_of_worship`

Ошибка сервера также реальна: действующий VK Maps endpoint в одном пробном запросе дал HTTP 200 за 16,439 с, в другом небольшом запросе - HTTP 504 за 0,493 с. Код превращает 504 в ровно то общее сообщение, которое увидел пользователь. Это наблюдение из нашей сети, а не установленная причина конкретного пользовательского запроса

Для 0.6 рекомендован прямой поиск названия через уже используемый Photon как основной путь. Он находит Сретенский монастырь без промежуточного Overpass и без геолокации. Проверены также другие названия в двух городах. Внешнюю выдачу следует показывать как найденные места с названием, типом и адресом, не приписывая ей проверенную конфессиональную принадлежность и расписание

## Что именно подтверждено в коде

- `ChurchScreen.kt`: первая строка "Город или название храма" ищет лишь среди добавленных; наружу ведет отдельная кнопка. Три разных поиска выглядят как похожие формы, но имеют разные области действия
- `ChurchDiscoveryScreen.kt`: `submitCity -> searchCities`; строка имени появляется только после `findChurches` и фильтрует уже полученный список. Пользователь не может найти храм по имени за пределами 3 км от географического центра выбранного города
- `PlaceDiscovery.kt`: Photon получает `layer=city`, Overpass получает только `amenity=place_of_worship`, `religion=christian`, разрешенные denomination. Монастырь как комплекс не проходит ни запрос, ни парсер
- `churchQuery`: `out center tags 60`, затем локальная сортировка. В московской пробе пришло ровно 60 объектов; это не доказательство, что в районе их ровно 60. Нельзя объявлять такую выдачу полным списком или гарантированно 60 ближайшими
- Округление центра до 0,01 градуса сохраняет примерную область, а не точную позицию телефона. Это существующее свойство надо сохранить
- `DiscoveryTransport.kt`: HTTP != 200, кроме 429, становится UNAVAILABLE; сюда же попадают DNS/TLS/прочие исключения. Сообщение не позволяет отличить отказ сервиса от отсутствия интернета
- INTERNET в manifest присутствует. По коду нет основания объявлять причиной отсутствие разрешения сети
- UI-тесты используют подмененный PlaceDiscovery. Они доказывают переходы и состояния, но не доступность сервиса на реальном телефоне

Официальные контакты указывают Большую Лубянку, 19, Москва: [контакты монастыря](https://monastery.ru/monastyr/kontakty/)

## Возможности и ограничения сервисов

| Вариант | Возможность | Решение для этой итерации |
| --- | --- | --- |
| Photon | Поиск названия/адреса, географический приоритет, категории, reverse; уже используется | Основной поиск по имени. Не требует нового SDK/ключа. Умеренные явные запросы и кэш |
| VK Maps Overpass | Выборка по православным тегам, координатам, сайтам; текущая интеграция | Сохранить только как отдельный ограниченный районный путь, если его UX и живой APK-проход приемлемы. Не оставлять обязательным посредником для любого поиска |
| Photon reverse | Быстрые ближайшие места по категории | Может быть запасным/основным поиском мест только при честном обозначении категории и отсутствии заявления "все православные". Не подменять им молча строго православную выдачу |
| Private.coffee | Оператор разрешает приложения, есть собственные условия | Не назначать автоматическим запасным только по обещанию: текущая и прежняя пробы завершились timeout |
| Публичный FOSSGIS | Общий Overpass с ограниченной емкостью | Не выбирать основным backend приложения: оператор прямо описывает это как проблемное применение, наша проба тоже timeout |
| Публичный Nominatim | Геокодирование | Не внедрять как быстрый запасной API: особые текущие ограничения для приложений/LLM, общий лимит всех пользователей, смена endpoint без обновления, запрет autocomplete |
| 2GIS Places / Yandex Organization Search | Поиск объектов и организаций по имени/адресу/району | Реальный следующий уровень для управляемого сервиса, но нужен ключ и согласованный тариф. Не обходить это выдранным ключом сайта или неофициальным endpoint |
| Собственный Photon/каталог | Контроль сервиса и данных | Не инфраструктурная "быстрая правка": нужен сервер, обновление индекса и эксплуатация. Для широкого выпуска оценить отдельно |

Photon разрешает умеренное использование публичного demo, но не обещает доступность. Планетарная установка требует существенных ресурсов; это не легкая локальная зависимость Android: [README оператора](https://github.com/komoot/photon#demo-server)

В API поддержаны фильтры по главным категориям. Современный `include=osm.amenity.place_of_worship,osm.amenity.monastery` проверен живым запросом. Фильтры по всем произвольным OSM-тегам не гарантированы; в наших ответах нет religion/denomination: [документация Photon](https://github.com/komoot/photon/blob/master/docs/api-v1.md), [категории](https://github.com/komoot/photon/blob/master/docs/categories.md)

Политика Nominatim: лимит 1 запрос/с относится ко всему приложению, обязательны идентификация/атрибуция/кэш и возможность смены сервиса без выпуска. Автодополнение запрещено. Текущая редакция отдельно ограничивает встраивание публичного API платформами генерации приложений; поэтому его нельзя рекомендовать как незаметную замену: [политика OSMF](https://operations.osmfoundation.org/policies/nominatim/)

Оператор FOSSGIS указывает, что публичная инфраструктура не должна становиться backend массового приложения; 429 и 504 относятся к разным ограничениям нагрузки: [руководство оператора](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)

Private.coffee разрешает использование в приложениях, требует бережных запросов и атрибуции, не дает гарантии доступности: [условия оператора](https://overpass.private.coffee/)

Для VK Maps найдено разрешительное описание в каталоге OSM, но это публикация сообщества, а не самостоятельно найденное соглашение VK. Не повышать его статус до SLA: [каталог OSM](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances)

2GIS требует ключ, предлагает демо или подписку и поддерживает текст/географическое ограничение: [официальный Places API](https://docs.2gis.com/en/api/search/places/overview). Яндекс требует apikey для Organization Search: [формат запроса](https://yandex.ru/maps-api/docs/geosearch-api/request.html), [условия](https://www.yandex.ru/legal/maps_api/ru/)

## Предлагаемый путь 0.6

1. Один явный вход "Выбрать храм". Сразу строка "Название храма или монастыря" с примером "Сретенский монастырь, Москва", кнопка "Найти" и отдельное "Рядом со мной". Сохраненные/избранные видны до сетевого действия
2. Локальные совпадения появляются сразу и ясно озаглавлены "Сохраненные". Явное сетевое действие ищет весь введенный запрос, а не только населенный пункт. Переносить введенный текст между выбором и внешним поиском, не заставлять печатать повторно
3. Основной запрос Photon `q=<полный ввод>&limit=10&lang=default&include=osm.amenity.place_of_worship,osm.amenity.monastery`. Нет скрытых цепочек "город -> центр -> 3 км -> фильтр"
4. Результат: название крупно; город/регион/улица ниже; вид "Монастырь" либо нейтральное "Место богослужения", если точная принадлежность не установлена. Не добавлять "православный" по одному имени. Не объединять разные OSM ID по близости координат
5. При выборе - краткая проверка места и местного времени с понятным "Выбрать этот храм". Расширенное редактирование можно оставить вторичным. Сохранение проходит существующий общий guard, отмена не стирает чтение. Часовой пояс нельзя рассчитывать только по долготе
6. После успеха возврат в основной сценарий выбранного храма. Если расписания нет, сразу предложить определить текущий момент. Не заканчивать путь пустым расписанием или длинной формой
7. При ошибке название остается. HTTP 5xx: "Сервис поиска сейчас не ответил"; рядом "Повторить" и "Добавить вручную". При районном отказе основной запасной шаг "Найти по названию". Не обвинять подключение пользователя при доказанном ответе сервера
8. Не развертывать цепочку трех бесплатных серверов: это умножает ожидание и раскрывает район нескольким операторам, а наши альтернативные пробы не подтверждают пользу
9. Сохранять небольшое число слотов кэша, существующую отмену/поколения запросов и ограничения ответа. Сохраненные выбранные храмы бессрочно доступны локально; давнюю выдачу ясно помечать датой
10. Для "Рядом" выбрать один из двух честных контрактов в проектировании: а) проверенные по тегам православные объекты через Overpass с ясным отказом; б) общий поиск мест через Photon reverse с явным подтверждением и нейтральными названиями. Не утверждать, что вариант б семантически равен а. Решение должен принять оркестратор после UX-пробы

Это предложение не означает, что публичный demo стал сервисом с гарантией. Оно убирает ненужную обязательную зависимость и решает подтвержденный сценарий прямого названия. Для публичного роста потребуется управляемый провайдер/свой сервис

## Допуск реализации и тесты

- Реальные fixture-ответы для Сретенского, другого одноименного монастыря, отдельного храма и Казани с несколькими конфессиями
- Полный ввод имени: один правильно кодированный запрос, без `layer=city`; специальные символы не меняют параметры
- Прием только валидных ID/координат/категорий, безопасные URL; missing city/address не заменяются выдуманными
- Сретенский монастырь и его два храма остаются отдельными вариантами
- Название/город из прямого поиска сохраняются при возвращении, ошибке, ручном вводе; повтор не требует печатать все снова
- 504, 429, timeout, отсутствие сети и malformed JSON дают разные правдивые состояния; повтор ограничен явным действием, 429 не запускает автоматический обход
- Отмена/уход/смена запроса отклоняют поздний ответ; нажатие дважды не сохраняет дважды
- Первый выбор, подтвержденная смена, отмена с полностью неизменными preferences
- Последующий запуск без сети находит сохраненный монастырь и открывает службу
- Натурный APK-проход на текущем эмуляторе: свежий поиск имени Сретенского, выбор, возврат, текст; еще одно название в другом городе. Записать реальный endpoint/статус/время, не только UI fixtures
- Отдельный проход без сети и после отмены; никаких бесконечных спиннеров
- Размеры/клавиатура/крупный текст: поле, результаты, отмена и действие выбора доступны без скрытого первого шага

## Границы результата

Не проверены сеть/телефон пользователя и доступность провайдеров из всех российских операторов. Настоящая причина его конкретного запроса не установлена. В наших пробах доказаны и работоспособный прямой поиск, и независимый отказ текущего Overpass. Статистическую надежность по этой небольшой выборке не вычислять

Скрипты воспроизведения сохранены только в `/private/tmp/feoria-v06-search-probe.py`, `...-more.py`, `...-nearby.py`; они создают новые каталоги и откажутся перезаписывать существующие свидетельства. Не запускать без необходимости: сохраненных ответов достаточно для реализации/регрессий
