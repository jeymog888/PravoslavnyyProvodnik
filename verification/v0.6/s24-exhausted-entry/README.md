# Шаг 2.4 - уточнение после предела расчета

Когда примерный порядок исчерпан, карточка не объявляет службу законченной: основной шаг открывает уточнение по словам или действиям. Следующая служба остается видимой. До подтверждения сохраняется прежнее чтение

Draft удерживает точные дату, начало, часовой пояс и источник выбранной службы, включая переход через полночь. Поиск Писания использует эту дату. Принятие атомарное и на паузе; поврежденный draft возвращает на главную с объяснением, поздние callbacks не меняют новый сценарий

## Проверки

- r1: 374 unit PASS; 31/34 UI PASS. Три исходных отказа сохранены
- Два test-only дефекта: substring assertion ошибочно требовал полный текст; диагностический visitor превращал посторонний MutableIntState в обычный MutableState. Исправлены без изменения runtime, оба метода PASS в r2
- Третий отказ повторился в r2. Экспорт диагностики не состоялся: root не создал обязательный каталог назначения до запуска. Приложение было удалено connected runner, снимок r2 не сохранен
- Отдельный diagnostic replay использовал те же APK/test APK с зафиксированными SHA. Отказ воспроизвелся. PNG и полные semantics доказали: кнопка find_stage y716..853 находилась ниже viewport y136..567, до и после нажатия тот же MAIN. Прокрутка контейнера находила большую карточку, но не выводила дочернюю кнопку
- Тест теперь дополнительно прокручивает саму кнопку и проверяет ее видимость перед настоящим нажатием. r3: этот метод 1/1 PASS, включая возврат и новый ориентир. Runtime не изменялся при исправлениях тестов
- 34 разных сценария имеют последние PASS, см. ui-coverage.json. Это совокупность r1/r2/r3, не полный повтор всех методов на r3. Production inputs совпадают, до/после каждой сборки неизменны
