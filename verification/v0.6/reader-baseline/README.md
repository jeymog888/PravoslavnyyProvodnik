# Исходные дефекты читателя перед переработкой

Это диагностическая база, а не приемка нового UI. Visual REJECT всех трех сцен намеренный: зафиксированы недостатки пользователя. Автоматический PASS у capture означает лишь совпадение заявленных экранных признаков и стабильный XML, не удобство. Итоговый строгий gate закономерно отвергает эти сцены; baseline-verdict.json фиксирует отказ

Установлен development APK этапа 2.1 SHA `67cb45bfc4d89a0ec3e78770efd50dfcdbfac627e06543218a4a8904a262cc35`. ServiceScreen и ServicePlaybackPlan побайтно совпадают с тегом v0.5.0-guide (проверено git diff). Другие изменения APK - защита смены храма, это не повторная установка опубликованной 0.5. Выбран Нахабино, приложение открыто обычным путем, "Читать с начала". Дата устройства 9 ноября 2026, шрифт 1.0, собственный API 35

Наблюдения root:

- Под "По-русски" показано редакционное описание подготовки, а не молитвенный текст. Тип содержимого не указан. Оригинал отключен, причина рядом не объясняется
- Play меняет кнопку на "По расчету / Переходы", описание остается неподвижным. Неясно, что именно происходит и к чему идет расчет. Статус добавляет высоту шапке и сдвигает содержимое
- В Meaning управление исчезло, но явного сообщения о паузе нет. Ссылка выглядит как название другого выбранного храма; метки "Источник пояснения" нет
- Большие вложенные поверхности и повторенные пояснения отнимают полезную область. Отдельная полоса "Уточнить" не раскрывает способ по звуку

Три PNG прочитаны root и независимым reviewer Astra: [отчет](independent-review.md). Оба подтверждают REJECT исходного UI и пригодность диагностической базы. Это не приемка еще не реализованного нового UI. Непосредственно после am start первое получение XML завершилось invalid XML; последующая свежая наблюдаемая сцена отработала. Сырой первый XML не сохранен, точную причину не утверждаем. Для следующих холодных запусков использовать am start -W и готовность окна перед деревом, а не скрывать ошибку автоматическим PASS
