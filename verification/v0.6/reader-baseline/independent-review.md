# Независимая проверка исходных PNG reader

Вердикт: REJECT как приемка UI, ACCEPT как диагностическая база для сравнения будущей переработки

Прочитан `app/build/verification/v0.6/reader-before-redesign/ROOT-BASELINE.md`. Независимо открыты все три `screen.png` из cases/preparation-paused, cases/preparation-playing и cases/meaning-source. Изображения 1080x2400 показаны инструментом с масштабированием до 922x2048. Это наблюдение PNG, не нативный запуск reviewer

## preparation-paused

- Вкладка "По-русски" содержит описание подготовки и советы, а не произносимый молитвенный текст. Рядом с переключателем нет явного названия этого типа содержимого
- "Оригинал" выглядит отключенным, причина не объяснена в видимой области
- Основная кнопка с иконкой Play названа состоянием "На паузе" и словом "Переходы", из нее неясно действие следующего нажатия
- Широкая внешняя белая поверхность, внутренняя зеленоватая карточка и отступы вокруг "Уточнить" уменьшают полезную площадь текста
- "Уточнить" не раскрывает наличие способа по звуку. Из PNG нельзя сделать вывод, есть ли такой способ на последующих экранах

## preparation-playing

- Основная кнопка теперь содержит "По расчету / Переходы", но отдельного ясного описания работы расчета и отсутствия звука нет
- Добавилась строка "Примерное место · можно уточнить", из-за чего вкладки и начало карточки сместились вниз относительно paused
- В кадре остается то же описание "До начала" без заметного текущего текстового ориентира. Два неподвижных PNG сами по себе не доказывают ни ход таймера, ни отсутствие прокрутки между захватами
- Следующий этап "Начало" виден, но причина и момент автоматического перехода из этого состояния пользователю не объяснены

## meaning-source

- После перехода в "Смысл" кнопка управления расчетом отсутствует, явной надписи о паузе в видимой области нет
- Внизу показана ссылка "Последование литургии Иоанна Златоуста, храм Пророка Илии" без метки "Источник пояснения". Она может восприниматься как текущий храм, особенно при отсутствии выбранного прихода в шапке этой сцены
- Несколько крупных отдельных карточек дробят связанное объяснение, сохраняя значительные отступы
- Верхняя карточка начинается с середины текста. Это допустимо для прокрученного кадра, само по себе не считается обрезанием layout

Наблюдения согласуются с ROOT-BASELINE.md и подтверждают необходимость пунктов 2.5/3.3/3.5. Они не доказывают качество еще не реализованного UI. Нельзя распространять вывод на темную тему, крупный системный шрифт, физическое освещение, акустику или мобильную сеть пользователя
