На PNG panel начинается примерно с середины физического экрана. Видны пункты от "Приготовимся к благодарению" до "Слова Тайной вечери", нижний пункт уже у границы navigation bar; "Приношение даров" не видно. За панелью остается выбранный "Свят Господь". Это подтверждает отсутствие target в физически видимой части partially expanded sheet в момент отказа. В данном capture не сохранены полные Compose roots с bounds, поэтому точное численное объяснение внутреннего measured viewport по одному PNG не объявляю доказанным. По коду тест прокручивает LazyColumn через semantics, но не раскрывает саму sheet; runtime использует обычный Material3 ModalBottomSheet без принудительного skipPartiallyExpanded

Минимальный корректный тестовый путь: открыть список, выполнить настоящий UI Expand action существующей панели либо жест раскрытия, дождаться завершения перехода, затем прежние scroll -> assertIsDisplayed -> performClick. Не вызывать напрямую player.selectTrack, не менять production SheetState ради теста, не ослаблять видимость до assertExists и не использовать повтор клика/теста как лечение

Если Expand отсутствует потому, что панель уже раскрыта, helper может продолжить исходную проверку target. Отсутствие Expand само по себе не должно объявлять target видимым. Если Expand найден, неуспех самого действия должен быть ошибкой теста, а не молча проглоченным исключением. Подпись или SemanticsActions должны соответствовать реальному action данной Material3, не новому test-only hook

Окончательный прогон должен сохранить прежние проверки выбранного title, заметок/голосов и неизменности reading при просмотре/языке. Эти два UI FAIL и diagnostic FAIL остаются отрицательными свидетельствами. Они не отменяют ранее независимо проверенную native upgrade цепочку, потому что production не менялся

Это не доказательство того, что любой пользовательский swipe уже проверен. Здесь допускается корректный реальный accessibility Expand путь для component теста, без утверждения о выполнении физического жеста или приемке финального редизайна
