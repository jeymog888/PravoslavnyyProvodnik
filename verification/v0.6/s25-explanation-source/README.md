# Шаг 2.5 - понятный источник пояснения

В "Смысле" вместо названия другого храма показано раскрытие "Источник пояснения". Внутри ясно обозначены назначение публикации, ее точное название, публикующий сайт и отдельная ссылка. Выбранный храм и источник материала различаются

Локальное раскрытие не меняет чтение и не вызывает сеть. Известная публикация сопоставлена по полному URL, другой адрес не наследует атрибуцию. Пустое название получает честный fallback; без адреса нет действия. Справка уточнена: Photon получает название храма или города, оба способа доступны без геолокации

## Проверки

- r1: сборка PASS, 4 целевых unit и 4 component UI PASS. Остальной набор здесь не повторялся, engine/assets/store не менялись
- Проверены context, speed SLOW, ненулевой offset, язык, пауза и число writer вызовов; раскрытие и закрытие не меняют их. Внешний callback получает ровно прежний URL один раз
- Реальный дефект самопроверки исправлен: inputs rememberSaveable сами не разделяют идентичность при восстановлении. Composition key теперь включает stage.id и URL. Смена этапа/URL при restoration не наследует раскрытие, тот же источник его сохраняет
- Нативно сняты свернутый/развернутый источник и две проверки при системном font_scale 2.0. Название и действие поместились одновременно, поэтому последние два кадра относятся к одной позиции прокрутки, не к разным состояниям
- Root и независимый reviewer просмотрели и приняли все четыре PNG в пределах этого шага. Текст переносится, публикация явно обозначена источником, отдельное действие достижимо. Общая перестройка reader и старые caps его шапки остаются этапом 3.5a
- Для выбора храма взята сохраненная fixture Сретенского монастыря, затем "Читать с начала" и "Смысл" открыты через UI. Это не новый live-поиск. Публикация в браузере не открывалась
- Нажатие раскрытия имело слабое условие ожидания той же подписи; само по себе это не доказывает раскрытие. Следующая записанная прокрутка и expanded capture доказывают появление сведений
