# Preflight 2.5 - источник пояснения

Решение: ACCEPT минимального контракта с перечисленными проверками реализации

Прочитаны раздел 2.5 разведки, ReaderMeaning, SourcesScreen, StageMatcher и два Photon пути. Самостоятельно открыта [первичная публикация](https://ikoni.cerkov.ru/posledovanie-bozhestvennoj-liturgii/kratkij-ustav-sxema-liturgii-svyatitelya-ioanna-zlatousta/): заголовок "Краткий устав-схема Литургии святителя Иоанна Златоуста", имя сайта "Сайт храма Пророка Илии" подтверждены. Это название публикации и публикующего сайта, не установленное авторство всего пояснения приложения и не выбранный пользователем храм

## Минимальная реализация

ReaderMeaning в ServiceScreen.kt:474-499 может заменить нынешнюю внешнюю кнопку с составным sourceTitle локальным раскрытием "Источник пояснения" в той же LazyColumn. При раскрытии показать назначение "Публикация, использованная при подготовке пояснения", название, публикующий сайт и отдельное "Открыть публикацию". Раскрытие/закрытие только меняют local UI state: без сети, смены экрана, нового Dialog и без вызова onOpenSource

Существующий callback внешнего открытия получает прежний точный URL. Сохранить действующий guard generation на уровне ServiceScreen.kt:223. State раскрытия привязан к stage.id и URL, смена этапа или URL сбрасывает его. Одинаковая публикация разных этапов не должна связывать их раскрытие. Обычная рекомпозиция не сбрасывает раскрытый блок

Exact-URL mapping единственной известной страницы допустим в presentation helper. Нельзя сопоставлять только домен, префикс или похожий путь: другой URL того же сайта не получает чужое название. Assets, Factory и отдельный источник PrayerTrack не менять

Fallback: непустой trimmed sourceTitle, иначе нейтральное "Публикация"; при наличии корректно извлеченного host допустима строка "Сайт: <host>". Host не называть неизвестным издателем. Не выводить длинный URL как непереносимую подпись. Null/blank URL не создает раскрываемое или внешнее действие. Парсинг host не должен выбрасывать исключение и не требует сети

## Исправление справки

SourcesScreen в SettingsScreen.kt сейчас утверждает, что Photon получает только город. PlaceDiscovery.kt:116-136 показывает два независимых запроса q: searchPlaces с названием храма и searchCities с городом. Достаточная точная замена:

"При внешнем поиске название храма или города отправляется в Photon, округленный район поиска - в VK Maps Overpass"

И в конце того же абзаца:

"Без разрешения на местоположение доступны поиск по названию храма или городу, ручное добавление храма и чтение"

Это описание реализованного поведения, без обещания работы внешнего поиска офлайн. Утверждения о микрофоне, кэше и остальном хранении данным изменением не расширять

## Проверки до приемки

- Избранный храм отличается от сайта источника: свернутая подпись нейтральна, развернутый блок ясно обозначает публикацию; открыть/закрыть не вызывает внешнего callback
- "Открыть публикацию" вызывает callback ровно один раз с прежним URL. Полный context, position, speed и язык до/после локального раскрытия одинаковы, плеер в Meaning остается на паузе
- Exact known URL, другой путь того же host, whitespace/пустой title, null/blank URL; без выдуманной атрибуции
- Смена stage при том же URL и смена URL при том же stage сбрасывают state. Recreation при том же этапе сохраняет согласованное состояние, если выбран rememberSaveable
- Нативный раскрытый блок при крупном тексте: название переносится целиком, внешнее действие достижимо прокруткой. Прежний nav/reader PASS не объявлять визуальной проверкой нового блока
- Короткая проверка текста SourcesScreen подтверждает оба Photon режима и доступность без гео, не требует нового сетевого запроса

Репозиторий не менялся, Gradle/adb/git mutations не запускались. Это согласование контракта до реализации, не приемка готового UI
