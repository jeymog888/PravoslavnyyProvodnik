## Личные наблюдения

- text: выделенная фраза "Миром Господу помолимся" различима по жирному начертанию, цвету и вертикальному маркеру. Ниже в одной ленте видны "Ответ хора", его строка и начало следующего фрагмента "О свышнем мире". Подписи типа, языка и голоса читаемы. Статус "На паузе", primary "Двигать текст" и 0,75x видны
- browse: после настоящей прокрутки видны другие фрагменты без ложного выделения. Верхний принятый фрагмент остается прежним, есть "К выбранной фразе". Primary, пауза и темп сохранились. Область ленты не изменила высоту при появлении Return
- returned: выделенная исходная фраза снова в viewport, Return исчез. Ее bounds в XML точно совпадают с text: [139,1145][975,1334]. Остальные видимые соседние фрагменты и paused primary согласованы с начальным кадром
- gospel-original: выбран "Оригинал", но видимое название прямо сообщает "По-русски · От Матфея 8:23-27". В ленте есть "Синодальный перевод. Церковнославянский текст пока не добавлен". Русская выбранная строка отмечена маркером; следующая строка не выделена. Никакого представления русского текста как добавленного церковнославянского на кадре нет
- missing: "Вонмем" показано обычным серым текстом без маркера; XML не содержит checked строк. Видно объяснение отсутствующего чтения на 9 ноября, статус паузы и один primary "Чтение в храме закончилось". Retained строка больше не выглядит текущей выбранной фразой. Return отсутствует

Часть следующего фрагмента на нижней границе text/browse/returned соответствует viewport прокручиваемой ленты, не является обрезанием неподвижной кнопки. Перекрытия primary или Return не видно. В text/browse/returned XML дает одинаковые границы scrollable [42,723][1038,1968], то есть 1245 px / 2,625 = около 474 dp по высоте. Это больше 120 dp именно в этой нормальной конфигурации. В gospel-original высота около 489 dp. На крупный шрифт или landscape это наблюдение не переносится

## Сохранность и происхождение

Проверены SHA/размеры всех артефактов пяти case, совпадение run/APK/manifest в каждом receipt. SHA фактических manifest.json, build.json и локального APK соответствуют run.json. Все пять capture имеют PASS, before/after XML внутри каждого case совпадают. В action receipts зафиксированы Resume, Return, порядок службы и выбор Gospel track; последовательность согласуется с кадрами

Три preferences.xml после text, browse и returned в supplemental/1794189096851763000, 1794189133811014000 и 1794189162282674000 побайтно равны, SHA256 52e1b8acc688a9f65753997e2f648493784b885860b2fe0d706ad045c9536812. В snapshot остаются дата 2026-11-08, MANUAL, segmentIndex 4, elapsedQuarterMillis 1234, SLOW и тот же planFingerprint. Это доказывает неизменность сохраненных байтов между контрольными точками; количество внутренних вызовов writer по этим файлам не выводится

Supplemental event.json содержит предварительный status ERROR, но соответствующие completion.json имеют RECORDED и согласованные run/APK. Я не трактую предварительный event как итоговую ошибку или дополнительный PASS. Raw observation не заменяет визуальное заключение

## Граница приемки

Снято на emulator API 35, 1080x2400, density 420, system font 1.0, light, обычный app text size, на паузе. Начальный Text и Missing заданы явно объявленными layout fixtures; после них выполнены реальные UI действия. Это не естественный arrival, не upgrade и не акустическая проверка. Надпись "Без звука" не доказывает отсутствие звука по записи

Для 3.5 остаются высокая шапка с отдельными строками даты/заметки, повтор названия и типа выбранного фрагмента над лентой, вложенная карточка Missing, объемная вторичная навигация. В normal конфигурации они не блокируют просмотр 3.4, но финальная композиция и масштабирование требуют отдельной приемки. Кадры не показывают все состояния, автодвижение, drag во время playing или boundary race; соответствующие тесты оцениваются отдельно. r3 три метода PASS сообщены root и отражены успешным build, я сам Gradle/adb не запускал
