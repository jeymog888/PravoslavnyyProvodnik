# Визуальная проверка главной страницы 2.3

Решение: ACCEPT для измененной области главной страницы при неизвестном расписании

Независимо просмотрены все 3 PNG из app/build/verification/v0.6/s23-home-native/cases: home-unknown, home-unknown-large-top, home-unknown-large-actions. APK: 71080a7160b310de0bb223591efb3df63967bfd37c8bc2274e8cba62a7c0a257

## Наблюдения

- home-unknown - выбранный "Сретенский монастырь" отделен от карточки службы. Сообщение об отсутствии данных не выглядит как назначенное время службы. Пояснение понятно связывает поиск со словами молитвы и происходящим в храме. Единственная заполненная основная кнопка - "Найти текущий момент"; "Указать начало литургии" визуально вторично. "Порядок службы" и "Читать с начала" остаются отдельными действиями
- home-unknown-large-top - имя монастыря переносится целиком, заголовок и пояснение читаемы, не перекрывают друг друга. Основная кнопка переносится на две строки без потери текста. Второе действие находится ниже видимой области
- home-unknown-large-actions - после прокрутки обе кнопки целиком доступны и различаются по приоритету. "Порядок службы", "Читать с начала" и нижняя справочная строка также читаемы. Верхний фрагмент пояснения у границы viewport - нормальный результат прокрутки, а не обрезание высоты самого текста

Уточнение после повторного просмотра отдельного PNG и чтения after.xml: первоначальное наблюдение о тесноте "Храм"/"Настройки" было ошибкой визуального просмотра и отозвано. В обоих крупных кадрах границы текста [482,2239][598,2310] и [787,2239][1026,2310] оставляют 189 px между надписями. Повторный просмотр подтверждает отчетливый пробел; дефекта нижней навигации по этим кадрам не установлено

## Условия и достоверность

Прочитаны manifest.json и все case.json. observed фиксирует emulator-5554, API 35, 1080x2400, density 420, Europe/Moscow; font_scale=1.0 для обычного кадра и 2.0 для обоих крупных. Независимо пересчитанные SHA-256 всех перечисленных artifacts совпали с case.json, before.xml и after.xml в каждом случае побайтно равны

Исходные case.json имеют visual_status=NOT_REVIEWED; настоящая запись фиксирует отдельное человеческое визуальное решение, а не выводит его из status=PASS сборщика

Это явная fixture сохраненного монастыря из предыдущего s22 native run. supplemental fixture event указывает исходный preferences.xml и SHA-256 7a9f61264636f733149b0ba58c304ae8f3ba14e9f4787af40215a1cd2f44d534. Manifest прямо ограничивает назначение проверки layout и отделяет первый выбор от этой съемки

Кадры подтверждают внешний вид и достижимость действий прокруткой, но не исполнение callbacks, маршрут первого выбора, новый live Photon запрос, offline, физическое устройство или акустику. Runtime в этой задаче не менялся; Gradle/adb не запускал. Восстановление font_scale=1.0 и оставшийся целевой UI-прогон этим review не проверены
